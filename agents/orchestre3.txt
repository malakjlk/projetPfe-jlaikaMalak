│  2.  Mettre à jour l'ORM (ex: Doctrine ORM vers la version 2.14+ ou 3.x)    │
│  pour assurer la compatibilité avec les attributs PHP 8.                    │
│  3.  Exécuter `composer update` et résoudre les conflits de dépendances de  │
│  manière isolée.                                                            │
│                                                                             │
│  ### Phase 3 : Résolution des Dépréciations et Changements de Rupture       │
│  (Breaking Changes)                                                         │
│  Cette phase traite des changements de comportement introduits entre PHP    │
│  7.4/8.0 et PHP 8.2.                                                        │
│                                                                             │
│  1.  **Propriétés Dynamiques Dépréciées (PHP 8.2)** :                       │
│      *   *Problème* : La création de propriétés non déclarées sur une       │
│  classe émet désormais un avertissement de dépréciation.                    │
│      *   *Solution* : Déclarer explicitement toutes les propriétés dans     │
│  les classes. Pour le code hérité difficile à modifier immédiatement,       │
│  utiliser l'attribut temporaire `#[AllowDynamicProperties]` ou implémenter  │
│  les méthodes magiques `__get()` et `__set()`.                              │
│  2.  **Fonctions Obsolètes et Supprimées** :                                │
│      *   Remplacer les appels à `utf8_encode()` et `utf8_decode()` par      │
│  `mb_convert_encoding()` ou par la classe `UConverter` de l'extension       │
│  `intl`.                                                                    │
│      *   Remplacer les fonctions de hachage ou de chiffrement obsolètes     │
│  (ex: fonctions `mcrypt_*` si encore présentes) par `openssl_*` ou          │
│  `sodium_*`.                                                                │
│  3.  **Signature des Méthodes Internes (`ReturnTypeWillChange`)** :         │
│      *   Pour les classes implémentant des interfaces PHP natives (comme    │
│  `ArrayAccess`, `Iterator`, `Countable`), ajouter le type de retour         │
│  correct ou utiliser l'attribut `#[ReturnTypeWillChange]` pour éviter les   │
│  alertes de dépréciation.                                                   │
│                                                                             │
│  ### Phase 4 : Modernisation et Adoption des Fonctionnalités PHP 8.2        │
│  Une fois le code compatible, nous exploitons les nouvelles                 │
│  fonctionnalités pour améliorer la qualité du code.                         │
│                                                                             │
│  1.  **Classes Readonly** :                                                 │
│      *   Convertir les DTO (Data Transfer Objects) et les Value Objects en  │
│  classes `readonly` pour garantir l'immutabilité des données :              │
│          ```php                                                             │
│          readonly class UserDto {                                           │
│              public function __construct(                                   │
│                  public string $username,                                   │
│                  public string $email                                       │
│              ) {}                                                           │
│          }                                                                  │
│          ```                                                                │
│  2.  **Enums (Énumérations)** :                                             │
│      *   Remplacer les classes de constantes de type "dictionnaire" par     │
│  des Enums natifs (introduits en PHP 8.1) pour un typage plus fort.         │
│  3.  **Types d'Intersection et Types Autonomes** :                          │
│      *   Utiliser les types d'intersection (ex: `Iterator & Countable`)     │
│  pour des contrats d'interface précis.                                      │
│      *   Utiliser `null`, `true` et `false` comme types autonomes dans les  │
│  signatures de fonctions.                                                   │
│  4.  **Promotion de Propriétés de Constructeur** :                          │
│      *   Simplifier les constructeurs verbeux en déclarant et initialisant  │
│  les propriétés directement dans la signature du constructeur.              │
│                                                                             │
│  ### Phase 5 : Validation, Tests et Assurance Qualité                       │
│  1.  **Mise à niveau de la suite de tests (PHPUnit)** :                     │
│      *   Mettre à jour PHPUnit vers une version compatible (PHPUnit 10+     │
│  recommandé).                                                               │
│      *   Exécuter l'ensemble des tests unitaires et d'intégration.          │
│      *   Corriger tous les avertissements (warnings) et dépréciations       │
│  remontés lors de l'exécution des tests.                                    │
│  2.  **Analyse des Logs de Dépréciation en Staging** :                      │
│      *   Déployer l'application sur un environnement de                     │
│  Staging/Pré-production configuré sous PHP 8.2.                             │
│      *   Activer la journalisation stricte : `error_reporting = E_ALL`.     │
│      *   Parcourir l'application (manuellement et via des tests             │
│  automatisés de bout en bout) et analyser les fichiers de logs pour         │
│  intercepter les dépréciations silencieuses.                                │
│                                                                             │

│                                                                             │
│  ## 5. Stratégie de Déploiement et Plan de Rollback                         │
│                                                                             │
│  Le déploiement en production doit être progressif afin de minimiser        │
│  l'impact sur les utilisateurs finaux.                                      │
│                                                                             │
│  ### 5.1. Déploiement Progressif (Canary Release / Blue-Green)              │
│  *   **Approche Blue-Green** : Préparer un environnement de production      │
│  parallèle (Green) sous PHP 8.2 pendant que l'ancien (Blue) tourne sous     │
│  l'ancienne version.                                                        │
│  *   **Canary Release** : Router un faible pourcentage du trafic de         │
│  production (ex: 5% à 10%) vers les serveurs exécutant PHP 8.2. Surveiller  │
│  activement les outils d'APM (Sentry, New Relic, Datadog) pour détecter     │
│  toute hausse anormale du taux d'erreur ou de la latence.                   │
│                                                                             │
│  ### 5.2. Plan de Rollback (Retour Arrière)                                 │
│  *   **Rétrocompatibilité des données** : S'assurer qu'aucune migration de  │
│  base de données effectuée pendant la transition ne casse la compatibilité  │
│  avec l'ancienne version de PHP.                                            │
│  *   **Bascule instantanée** : Conserver la capacité de modifier            │
│  instantanément le routage réseau (Load Balancer) ou de réinitialiser les   │
│  conteneurs Docker vers l'image de l'ancienne version de PHP en cas         │
│  d'anomalie critique non détectée lors des phases de test.                  │
